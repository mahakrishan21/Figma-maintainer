# Token benchmark: v1.36.0 vs v1.37.0 (25 Nov 2026)

The approach applies the Code Mode idea locally: heavy reading and filtering run in scripts, and only answers enter the conversation. There's no Cloudflare deployment. Cloudflare's Code Mode runs only on Workers, it's experimental, and `use_figma` already executes code inside Figma.

## 1. Fixed context per step (measured)
Every API request an agent makes re-sends its fixed context: Claude Code's system prompt, the tool definitions and the agent's instructions. These figures are measured with `claude -p`:

| Setup | Fixed context per request |
|---|---|
| Subagent that inherits all tools (v1.36 agents) | 35,062 tokens |
| Same, with `disallowedTools` (v1.37 agents) | 9,737 tokens |
| Same, with a strict `tools` list (Bash, Read, Write, Edit, Glob, Grep) | 4,981 tokens |
| Real `figma-maintainer:qa-checker`, v1.37 | 13,856 tokens (historical median 32,952) |
| Main session, MCP servers off (for comparison) | 45,082 tokens (49,672 with MCP) |

**Why it matters:** the unused built-in tool definitions (Artifact, Workflow, Agent, Skill, plan mode, scheduling and so on) cost about 25k tokens on every step of every agent. MCP tool definitions are already loaded only when needed, at about 4.6k tokens. A strict `tools` list would save a little more, but it isn't used: Figma MCP tool names differ between Macs (`claude_ai_Figma`, `figma`, …).

## 2. Paired runs on the same input (measured)
Each pair ran the same prompt in headless `claude -p`, with `--plugin-dir` set to v1.36.0 (a git worktree) or to v1.37.0.

| Job | v1.36.0 input | v1.37.0 input | Change | Cost | Quality |
|---|---|---|---|---|---|
| Comment analysis, PIPP round of 26 Oct (client-comments) | 451,561 · 13 calls | 263,655 · 10 calls | **−42%** | $0.76 → $0.57 | Same 4 verdicts. v1.37 checked each one in the file and added `Check:` lines. |
| QA on the Kayben round-2 pair 610:1364 → 737:187 (qa-checker) | 525,509 · 13 calls | 483,164 · 18 calls | **−8%** | $0.60 → $0.63 | Same overall verdict and the same verdict for each of the 6 items. v1.37 gave more exact evidence. |
| Copy edit on FM-Test, Sonnet (figma-maintainer) | 642,632 · 14 calls | 282,721 · 11 calls | **−56%** | $0.52 → $0.47 | Both stopped before editing: the Figma connector's rate limit for this account's View seat. |

**QA result:** the v1.37 QA agent spent the savings on extra digging: a glob of the whole project folder (15k characters) and reading the full summary again. The agent now has a rule against both, so this pair should improve on a re-run.

**Copy-edit result:** this pair measures the startup and fixed overhead, not a finished edit. The Figma MCP refused calls in both runs ("tool call limit for your View seat on the Professional plan").

## 3. Replay estimate over the 39 logged tasks
This replay uses `token_bench.py` with the what-if model. It weights each tool result by the number of later requests that re-read it, then applies the new caps:

| Agent | Tool-result context before | After | Change |
|---|---|---|---|
| client-comments | 10.1M tokens | 6.9M | −32% |
| figma-maintainer | 30.1M | 23.4M | −22% |
| qa-checker | 9.6M | 4.9M | −49% |

The fixed-context saving comes on top of this: about 25k tokens × requests, or roughly 0.85M per median figma-maintainer task of 34 requests.

Baseline numbers per agent and per tool kind are in `2026-11-baseline.md`.

## How to measure again
```
python3 -I scripts/token_bench.py --since 2026-11-26 --md docs/benchmarks/<date>.md
```
Compare it with `2026-11-baseline.md`: median input per task, images, and characters per tool kind.
