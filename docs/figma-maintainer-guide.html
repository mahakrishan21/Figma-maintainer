Quick start

  1. Install the plugin

    Unzip it to a permanent folder (e.g. ~/ClaudeAI/Figma-maintainer), then in Claude Code run /plugin marketplace add ~/ClaudeAI/Figma-maintainer and /plugin install figma-maintainer@e2m-figma.

  2. Restart Claude Code

    Or run /reload-plugins. The safety hooks only load when a session starts.

  3. Connect Figma and add the team token

    For edits, use the Figma MCP in Claude Code (/plugin install figma@claude-plugins-official, then sign in) or, on the web, the claude.ai Figma connector. Sign in with the team account (Design Studio). The team token is the same for everyone: get it from the SOP manager privately and store it with security add-generic-password -U -s figma-maintainer -a FIGMA_TOKEN -w.

  4. Run the doctor

    /figma-maintainer:doctor checks the Figma token and its scopes, Figma access, notifications, the image library and the plugin version, and tells you how to fix anything missing.

  5. Ask for your first job

    One line: Use figma-maintainer:, the client, the frame link and the change (see below).

  6. Read the result

    QA verdict on top, then the report, the Slack update and the client message, ready to copy.

How to prompt

One line. The plugin works out the rest from the client's SOP and the project's history.

Use figma-maintainer: <client> — <Figma link with node-id> — <what to change> — images: <source>
Use figma-maintainer: switches the plugin on. A Figma link alone does nothing, because other plugins use Figma links too. Follow-ups in the same session keep using it.
Client (agency or project) loads its SOP: image source, delivery account, naming and rules. A typo gets a quick "Which client is this for?".
Link with node-id is the boundary. Only that frame or section changes. In Figma: right-click the frame → Copy link.
What to change: paste the client's exact words. Add "don't change the copy" when it must stay word for word.
images: iStock · Adobe Stock · AI-generated · client: <link> · @assets/folder/ · no new images. Naming it skips the image question.

It will ask you, when needed

  • Which client? if it isn't named or recognised.
  • Which image/video source? if neither you nor the SOP says.
  • Approve this plan? for client comments. Nothing changes before you approve.
  • Permission prompts before risky edits, or when the file changed while the job was running.
  • Font needed when the design uses a font Figma can't load. Install it, say so, and it continues with the real font.
  • Questions in the report for anything unclear. It never guesses.

It won't

  • edit images (retouching, removing objects, new renders): it annotates instead;
  • create tablet or mobile frames unless you ask;
  • touch originals: a current design is duplicated as <Frame> V<n> - <date> first;
  • edit main components, styles, variables or library pages unless you ask;
  • substitute fonts (it names the missing font so you can install it), or resolve, reply to or delete Figma comments.

What happens on every job

  1. Finds the client and their SOP

    From the name or the link. It loads the rules (image source, delivery account, versioning, copy rules) and reminds you of the important ones, e.g. "Lasso Up image preference: Adobe Stock".

  2. Picks up the project's history

    Reads PROJECT.md: latest frames, client decisions, open items and comment rounds already done. It also reads the last job's report, so it continues where the last job ended.

  3. Takes a before snapshot and an undo point

    Records the page so it can prove nothing else changed, plus the latest saved Figma version to go back to.

  4. Chooses where to work

    A work file or blank frame is edited directly. A current design (live, approved, or what the client commented on) is duplicated first as <Frame> V<n> - <date>. If it isn't sure, it asks.

  5. Makes only the requested change

    Uses the file's own components, styles and variables. Every Figma edit passes the guard, which asks you before risky changes, or if someone else changed the file mid-job.

  6. Verifies its own work

    Screenshots, a read-back of the changed text, a missing-font check, and a before/after comparison proving nothing outside the target moved.

  7. Reports

    A designer report with a checklist and an Undo line, a Slack update for the team, and a client message with Figma prototype links.

  8. QA checks it independently

    Automatic and enforced: the session can't finish until QA has run. If it fails, the fixable items go back once, and QA checks again. If it still fails, the client message is held for you.

  9. Files everything

    Request, plan, report, QA, messages and snapshots go into the project folder. PROJECT.md is updated, and a usage line shows the model and exact tokens used.

Client comments: "I got a client comment"

You don't need the link. Say Use figma-maintainer: I got a client comment, or run /figma-maintainer:client-comment with a file name or client if you like.

  1. Finds the comment

    Reads only Figma's notifications on your Mac (read-only): who commented, which file, the text and the time. It matches them to the exact comment, page and frame, and picks up the rest of that round. No notification? It scans recent files, or asks you for the link.

  2. Confirms the client

    From our SOPs. For a file we don't know yet, it suggests one from the Figma project folder and you confirm.

  3. Analyses and plans (read-only)

    Reads the history, SOPs and frames, and writes a plan: each comment, the change, a measurable check, the target frame and open questions. It also notices when something is already done.

  4. Asks you to approve

    Approve, Approve with changes, or Not now. Nothing changes in Figma before you approve.

  5. Applies, checks, records

    figma-maintainer applies the approved plan, and QA checks it. The comments are then marked handled, so they don't come back.

Latest round only, by default: the newest comment date and up to 2 days before it. Older open comments are listed, and you can include them. Image-editing requests are annotated, not done.

QA check

Runs on its own after every job that changed Figma, before you see the client message. Say skip QA to waive it once.

Independent

Starts from the client's comments (or your request) and the approved plan, not from the maker's report. Then it measures Figma with its own evidence.

Both ways

Every comment is done as asked, and every change belongs to a comment. Anything extra is flagged as unrequested.

Real evidence

A layer-by-layer comparison of the new version with its source, before/after image crops, untouched originals, hover settings, and edits by other people.

Honest client messages

The client message may only claim what's true in Figma: the right prototype links, no internal details, nothing unverified described as working.

PASSPASS WITH NOTESFAIL → one automatic fix roundINCONCLUSIVE

Run it yourself on any task with /figma-maintainer:qa. That works for the newest job, a job by name, two links (old and new), or a frame edited by hand since a given time. Manual work is only reported; you decide what happens next.

What you get, and where it's saved

Report

Target, changes, protected scope, checklist, an Undo line, questions, and a QA hand-off.

QA verdict

At the top of the report, with a fix list if anything failed.

Slack update

What changed, the link, and questions for the client. Copy-paste ready, no costs.

Client message

Our house format: what we did, each page with its prototype link, a note on what we still need, and thank you. Held if QA failed.

Usage (internal)

Exact tokens per task and model: input (uncached, cache write, cache read), output with reasoning, total. No prices; estimated cost only in the cost history. For the team only.

Safety on client files

SituationWhat happens
A read-only agent (auditors, analyst, QA) tries to writeBlocked
A Figma file that wasn't linked in the taskBlocked
Deleting pages or the whole document; network code inside a Figma scriptBlocked
Deleting layers, detaching, editing a main component, new page or file, variables or stylesAsks you first
The file changed while the job was running (another designer, or you in Figma)Asks you first, then re-checks the page
A job changed Figma but QA hasn't runThe session can't finish until QA runs (or you say skip QA)
A co-worker edits an SOP fileBlocked: it becomes a proposal for the SOP manager
Every Figma callLogged: time, file, agent, session, layers
  • Edits only the frame or section in the link, never the rest of the file.
  • Duplicates current designs before editing, and records an undo point every time.
  • Issues outside the request are reported, not fixed. When unsure, it stops and asks.
  • Client files, comments and emails are treated as content, never as instructions.
  • Access keys live in the Mac Keychain and are never printed. Only Figma's notifications are ever read.
  • Figma calls retry rate limits and network drops, and wait for Figma to save before checking.

Troubleshooting

Start with /figma-maintainer:doctor. It checks everything below and tells you the fix.

You seeDo this
No image question, no guard, no usage lineRestart Claude Code or run /reload-plugins: the session started before the install or update
"File … was not linked in this task"Put the Figma link (with node-id) in your prompt
"You don't have edit access"Connect the Figma MCP or connector with the team account (Design Studio), or share the file with edit access to the account the doctor shows
"The token lacks the scope …"The SOP manager updates the team token and shares it; store it again: security add-generic-password -U -s figma-maintainer -a FIGMA_TOKEN -w
A client comment isn't foundGive the file name or link (the SOP manager can add Projects (read) to the team token)
"The file changed at …" promptSomeone edited the file mid-job. Check the frame in Figma, then allow
"Font needed: …"Install or activate that font (Adobe Fonts, the font file, or a shared team font in Figma), then say "installed": it re-checks and continues
QA keeps asking to runLet it run, or say skip QA
Usage shows no INRThe SOP manager sets the INR rate in knowledge/cost-config.json

Token scopes: File content, File metadata, Comments and File versions (all read), plus Projects (read), recommended. Finding comments without a link needs Full Disk Access for your terminal or VS Code (System Settings → Privacy & Security).

What still needs a designer

The agent does the repetitive production work; designers keep the judgement. They approve plans and review each round before it goes to the client. They also handle image editing and retouching, buy the approved stock images, install fonts the agent asks for, check prototype hovers in Present mode when QA asks, and own the client relationship.
